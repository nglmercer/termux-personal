# Implementation status against the unified SDK, jobs, files and workspaces spec

This file records what the repository implements, what was verified and where, and what remains. It is not a release claim. The spec's acceptance criteria are not met for PR 3 through PR 6, and PR 2 still has device checks open.

Host verification: Linux x86_64, JDK 21 (`/usr/lib/jvm/java-21-openjdk`), the cached Gradle wrapper offline, NDK 29. Device: Xiaomi 22021211RG (`3335b0fd`), Android 14, kernel 4.19, arm64-v8a, debug build installed over ADB.

## Running-job control

Kernel 4.19 lacks `clone3`, pidfd signalling and `close_range`, so managed jobs use the owned child launcher described in `managed-jobs-appshell-audit.md`. The app forks the child itself, waits without reaping (`WNOWAIT`), and signals only before marking the child exited, so a signal can never reach a recycled PID. `system.describe` reports `limits.jobStopAvailable`. If the native library cannot load, it is `false`, and timeouts and running-job cancel return `UNSUPPORTED` as before.

## Next steps, in order

1. Install the instrumentation APK and run `OwnedChildProcessInstrumentedTest` and `ManagedNativeInstrumentedTest` in the app process.
2. Re-enable local control with every job, process, file and workspace box, then run `scripts/test-control-jobs-device.sh` (cancel, timeout, signal, files, workspace Git).
3. Richer UI. The long-press menu now has Managed jobs (list, newest 16 KiB of each stream, cancel), Files (read-only browsing of `home` and `prefix` through the race-safe access, links listed and never opened, UTF-8 previews of the first 16 KiB) and Workspaces (list, presets, and "Open terminal here", which starts a new session in the workspace directory and leaves existing sessions unchanged). All three are dialogs that load off the main thread and are untested on a device: adb input injection on this Xiaomi needs "USB debugging (Security settings)". Not built: file editing, multi-select, SAF picker, image preview, a process tree with job actions, and running presets from the UI.
4. Optional: a durable job journal. Spec §4.3.6 allows documenting service-lifetime history instead, which is the current behavior: job records and output live in memory, a service restart forgets them, and no job is ever reported as surviving a restart.
5. Second ABI and API level, signed release and upgrade path.
