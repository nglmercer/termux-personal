# termux-control package draft

This recipe packages the native client for the opt-in local control socket in the Termux Next Generation app fork. The listener is disabled by default and the client does not enable it. It is not compatible with an app that lacks that experimental protocol. All processes running under the app UID share the locally selected scopes; output access and force-close access require separate opt-ins.

This directory preserves the separate Termux package recipe alongside the personal app source; a Termux packages checkout or compatible build environment is still required to build it. The source URL and checksum pin a draft personal-repository commit so the recipe is reviewable. **Do not publish this package as an upstream release:** first merge or publish an accepted stable source, update the URL, checksum and version, review the protocol and permissions, and run the normal Termux package builder and Android device matrix. A new package must not be added to the bootstrap without an explicit compatibility and upgrade plan.

The previous source revision was exercised using the recipe build and install hooks in a private staging directory on an Android ARM64 Termux host. Its staged binary passed host mock Unix socket and interactive pseudo-terminal reconnect tests. The source archive for this personal-repository pin has been checksum-verified; its package hooks have not yet been run. Earlier source revisions were also assembled into an ARM64 `.deb` and cross-compiled for ARM, i686 and x86_64; those checks have not been repeated for this revision. This is not a standard `build-package.sh` build, a published package, or a device test of Android LocalSocket or a live PTY. The normal on-device package builder installs intermediate files into the live Termux prefix; this sandbox did not permit that, so it was not run.

When an appropriate isolated Termux build environment is available, build with the repository's supported `./build-package.sh termux-control` and verify the resulting package, installation, removal, upgrades, each ABI, peer credentials, listener consent, and behavior against matching app versions before release. Do not overwrite an existing official Termux installation to test a differently signed app.
